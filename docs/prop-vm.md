# Prop Fund split deployment

The Mac is the control host. It runs PostgreSQL, the control API, the
calculation worker, and the Vite dashboard. The Windows VM runs NinjaTrader and
the outbound-only `PropFund.NinjaTraderAgent`. NinjaTrader's loopback bridge is
never reachable from the Mac or the host-only network.

## Mac control host

The Mac configuration in `homes/macbook-pro-m4/local/prop-control.nix` manages
all local processes through launchd. Activate it with:

```bash
just home-switch ianmh@macbook-pro-m4
```

It creates private operational state in `~/.local/state/prop-control`:

- PostgreSQL is loopback-only on `127.0.0.1:5432`.
- The browser API is loopback-only on `127.0.0.1:8788`.
- The dashboard is loopback-only at `http://127.0.0.1:5173`.
- Caddy listens only on the Mac's VMware host-only address `172.16.42.1:8443`,
  requires the VM agent's client certificate, and proxies exclusively to the
  loopback API.

The database password, browser API token, and local CA keys are generated
locally with restrictive permissions; none are committed to Nix or the project
repository. Check the services with:

```bash
prop-control-status
```

The first dashboard visit asks for the local API token. Reveal it only in a
private terminal when needed:

```bash
set -a; source ~/.local/state/prop-control/control.env; set +a
printf '%s\n' "$PROP_CONTROL_AUTH_TOKEN"
```

## Windows VM boundary

The VM's host-only adapter is `172.16.42.128`; it may use NAT for normal
outbound internet access but has no bridged or forwarded ports. Operational
traffic is deliberately outbound-only: the agent calls the Mac over mTLS, and
the NinjaTrader bridge remains loopback-only. `prop-vm-host` resolves the VMware
lease, and `prop-vm-status` confirms that bridge ports are not exposed to the
Mac.

The existing `~/.ssh/prop-vm` key is generated by the Mac Home Manager
activation for optional administrative access when VMware Fusion supports
host-to-guest forwarding. No SSH dashboard tunnel is used or required: the
dashboard and backend live on the Mac.

## Optional Windows SSH hardening

If administrative SSH is available in the VM network configuration, constrain
OpenSSH in an elevated PowerShell session as follows. The control system does
not rely on this path.

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
Disable-NetFirewallRule -Name OpenSSH-Server-In-TCP -ErrorAction SilentlyContinue
New-NetFirewallRule `
  -DisplayName "SSH from Mac host-only only" `
  -Direction Inbound -Action Allow -Protocol TCP -LocalPort 22 `
  -LocalAddress "172.16.42.128" -RemoteAddress "172.16.42.1" -Profile Any
```

Configure `sshd_config` to listen only on `172.16.42.128`, disable password
authentication, and use the contents of `~/.ssh/prop-vm.pub` as the permitted
Windows user's public key. Verify the SSH host key on the VM before adding it
under the `prop-vm` alias on the Mac.

After the Mac control host is active, copy these two generated files to a
private VM directory such as `%LOCALAPPDATA%\PropFundControl\pki`:

- `~/.local/state/prop-control/pki/ca.crt`
- `~/.local/state/prop-control/pki/prop-vm-agent.pfx`

Import `ca.crt` into the current Windows user's **Trusted Root Certification
Authorities** store. The PFX is the client identity used only by the agent; keep
it readable only by the Windows user running NinjaTrader.

The agent uses this private control endpoint:

```text
https://172.16.42.1:8443
```

It requires the PFX for both enrollment and normal operation. The control host
does not have, log, or transmit `PROP_NT_BRIDGE_SECRET`.

## NinjaTrader safety gate

The VM currently has NinjaTrader installed. Do not overwrite the AddOn, set a
new bridge secret, compile Custom, or restart NinjaTrader until every account is
flat and has no working orders. Once it is safe, use the project’s
`integrations/NinjaTrader8/tools/Install-PropFundBridge.ps1` to verify and then
install the canonical AddOn. Create or retain a high-entropy
`PROP_NT_BRIDGE_SECRET` in the Windows user environment, restart NinjaTrader,
compile Custom, and enable the AddOn.

Then enroll and run `PropFund.NinjaTraderAgent` with
`PROP_CONTROL_URL=https://172.16.42.1:8443`, the client PFX path, an agent ID,
and a short-lived enrollment token created from the authenticated Mac dashboard.
The agent stores its bridge secret and central token in CurrentUser DPAPI state;
its only network path is the mTLS connection back to the Mac.
